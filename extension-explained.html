Chrome Extension

Chess.com Board Detector

This project is a Manifest V3 browser extension that runs on Chess.com pages, reads the visible chess board, classifies the page as live, replay, analysis, or unknown, and publishes a structured detection result inside the page.

What It Watches

It loads only on https://www.chess.com/*. A content script starts after the page is idle and watches board, clock, move-list, and control changes.

What It Extracts

It can produce a board map, FEN placement, orientation, mode confidence, evidence, source, game id, and optional PGN/FEN from Chess.com replay or analysis share data.

Important Gate

Live Games Are Blocked

Sharing is disabled for live and unknown games. Replay and analysis pages are allowed only when mode detection is confident enough.

Plain-English Explanation

The extension is not a chess engine and it does not make moves. Its job is to observe the current Chess.com page and convert visible page state into structured data. It detects whether the page looks like an active live game, a completed-game replay, or an analysis board. Then it tries to read the board position from the DOM, reconstruct a FEN placement, and report how confident it is.

How It Works

Load settings

The popup stores settings in chrome.storage.sync: enabled, debug mode, debounce delay, and fallback scan interval.

Watch page changes

PageWatcher reacts to Chess.com DOM changes and waits briefly before running detection, so one move animation does not trigger many full scans.

Classify the page mode

ModeDetector looks for signals such as resign/draw buttons, clocks, replay controls, analysis layout, and game-over controls.

Apply sharing rules

ShareController blocks live games, unknown pages, and low-confidence mode results before replay or analysis data can be treated as shareable.

Read or reconstruct the position

BoardReader reads piece elements and square classes. For replay or analysis pages, the pipeline can also use Chess.com share data or reconcile the move list with chess.js.

Publish a result

The content script dispatches a chesscom-board-detector:result browser event. In debug mode, it also logs and renders a preview.

Main Files

manifest.json

Defines the extension name, Chess.com host permission, popup page, storage permission, and content script entry point.

src/content/index.ts

Starts and restarts the detector from stored settings, dispatches detection results, and handles debug preview behavior.

src/detector/pipeline.ts

Coordinates the full detection cycle: mode detection, sharing decision, fingerprint cache, board read, share extraction, and move-list fallback.

src/detector/boardReader.ts

Converts Chess.com DOM piece classes and board orientation into chess squares, board maps, and FEN placement strings.

src/detector/shareController.ts

Centralizes the safety rule: live and unknown game states are not shareable, while confident replay and analysis states are allowed.

popup/index.html

Provides a small settings UI for enabling the detector, turning on debug output, and tuning scan timing.

Typical Result

A successful detection result can say: status is ok, game id is known, mode is live, board confidence is high, orientation is white or black, source is board-dom, and sharing is blocked because the reason is live-game.
