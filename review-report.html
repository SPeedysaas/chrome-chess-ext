Prioritized Findings

Ordered by likely user impact and operational risk.

High

Old async work can republish stale positions after a detector restart

The content entry point stops and disposes the active controllers when settings change, but outstanding share-PGN and debug update promises are not canceled or associated with a run generation. When an old promise resolves, it can call publishResult with an obsolete game/position and the old settings/controllers.

Impact: toggling settings or navigating while enrichment/analysis is in flight can restore debug UI that was just disabled, display stale overlays, or recreate Stockfish workers through a controller that was already disposed.

Evidence: src/content/index.ts:71-75, src/content/index.ts:80-85, src/content/index.ts:210-216, and async debug continuations at src/content/index.ts:137-151. The restart path disposes the old watcher at src/content/index.ts:288-296, but no generation/abort check guards later callbacks.
Medium

The popup silently resets the attack-balance preference

attackBalanceOverlay is a real persisted setting used by the content script, but the popup has no control for it and omits it from both form application and form reads. Saving any unrelated popup change normalizes the missing field back to its default value of true.

Impact: users who disabled attack-balance badges through existing storage or an earlier UI cannot preserve that choice; a routine Save re-enables the feature without indicating it.

Evidence: declared/defaulted in src/extension/settings.ts:6,23,50; consumed in src/content/index.ts:115-119; absent from popup/index.html and src/popup/index.ts.
Medium

Transient share-dialog failures are permanently suppressed for that position

The automation key is inserted before opening/reading the share dialog. It is never removed when the read returns null or rejects, so later mutation and fallback cycles skip the same position forever.

Impact: a slow-rendering or temporarily changed Chess.com modal can leave the extension stuck with lower-confidence move-list data until the position key changes or the extension restarts.

Evidence: src/content/index.ts:204-224. The key should represent successful enrichment, or failures should clear it with bounded retry/backoff.
Low

The returned watcher handle exposes an unbound start method

startChessComBoardDetector returns start: watcher.start. For the real PageWatcher class, calling the returned handle's start() changes the method receiver, so internal calls such as this.stop() run against the wrapper object rather than the watcher.

Impact: the public restart handle is unreliable even though initial startup and the currently used stop() path work.

Evidence: src/content/index.ts:79-85 and instance-state access beginning at src/content/pageWatcher.ts:18. Return start: () => watcher.start() or bind the method.
Low

The test suite is red because a packaging assertion no longer matches the build

The popup is bundled with esbuild, so its dependency code is correctly inlined. A manifest test still expects a literal from '../extension/settings.js' import in the generated bundle, which is incompatible with the current build command.

Impact: CI cannot provide a clean regression signal, and a genuine failure can be obscured by the known red baseline.

Evidence: package.json bundles src/popup/index.ts; failing assertion at tests/extension/manifest.test.ts:32-36. Current result: 1 failed, 268 passed.

Architecture Assessment

The project is generally well-factored for an extension of this size.

Detector layer

Clear separation between DOM reading, mode inference, reconciliation, tactical analyzers, and result typing. Fixture coverage is strong.

Engine layer

Local Stockfish access is isolated behind small interfaces, with cancellation IDs protecting most result application paths.

Content layer

Feature overlays fail independently, but the central orchestrator needs a run-level lifecycle token to make those boundaries reliable across restarts.

Recommended Order

A small sequence that restores confidence quickly.

  1. Add a detector run generation or abort signal and guard every async continuation before publishing or rendering.
  2. Add the missing attack-balance popup control and regression coverage for preserving the field while saving another setting.
  3. Clear failed share-automation keys and use bounded retry/backoff.
  4. Wrap the returned watcher methods so their receiver is stable.
  5. Replace the obsolete popup import assertion with a runtime-oriented bundle check, then restore a fully green suite.
